## 2026-06-14 Tek-Node Sunucu ve No-AI Güncellemesi

Bu güncelleme, üzerinde çalışılan makinede ölçülen 4 vCPU, 7.8 GiB RAM, 2 GiB swap ve 28 GiB boş disk profiline göre planı daraltır. Dosya adı `prod-plan-2026-06-12.md` olduğu için bu analiz 12 Haziran 2026 tarihli prod planının devamıdır; istemdeki "2026 12 06" ifadesi bu yerel dosyayla 12 Haziran 2026 planı olarak eşleştirildi.

- **Çalıştırma hedefi:** Tek VPS/tek Docker Compose stack; web, API, worker, queue-board, Postgres, Redis ve MinIO aynı host üzerinde. Observability ve external monitoring ayrı override/profil ile yalnız kanıt üretimi veya staging doğrulaması sırasında açılır.
- **Kaynak tavanları:** `docker-compose.yml` varsayılanları web 0.75 CPU/768 MiB, API 1 CPU/1 GiB, worker 1.5 CPU/2 GiB, Postgres 1 CPU/1.5 GiB, Redis 0.5 CPU/512 MiB, MinIO 0.5 CPU/768 MiB olarak ayarlandı. Node heap tavanları `.env.example` içinde verildi.
- **ClamAV:** Upload AV üretim kanıtı için korunur ama varsayılan stack'te çalışmaz; `clamav` servisi `av` profiline alındı. Fail-closed AV kanıtı gerektiğinde `docker compose --profile av up -d` ile açılır. Günlük geliştirme/pilot çalışmada bu, yaklaşık 1-1.5 GiB RAM boşaltır.
- **AI kapsamı:** Bu release'te AI/LLM veya AI olarak pazarlanacak template karne yorumu eklenmez. `AI_REPORT_SUMMARY_PROVIDER=disabled` production/staging sözleşmesi haline getirildi; `template` modu yeniden açılacaksa ayrı DEC, KVKK değerlendirmesi ve ürün sahibi onayı gerekir.
- **Öncelik değişikliği:** Faz 8'de AI POC hattı kaldırıldı. Kaynaklar önce canlı ortam, backup/restore, RLS live, optik→karne döngüsü ve panel kullanılabilirliği üzerine harcanacak.

## 4. Bloklayıcı Riskler (prod'a çıkışı durduranlar)

1. **Tenant izolasyon bütünlüğü kanıtlanabilir değil (A1+A2).** "Kurumlar birbirinin verisini asla göremez" sert kabul kriteri; bugün en az bir tabloda RLS yok ve denetim mekanizması yeni tabloları yakalamıyor. *Stop-rule: A1+A2 kapanmadan hiçbir gerçek kurum verisi sisteme yüklenmemeli.*
2. **Release gate güvenilmez (B1+B2).** Kırık `pnpm run ci` + GitHub/lokal drift varken "repo gate PASS" iddiası anlamsızlaşıyor.
3. **Canlı ortam hiç kanıtlanmadı (C3).** Staging yok; HTTPS, backup-offsite, restore drill, alert zinciri hiçbir gerçek ortamda koşmadı. Mock/demo kanıtla prod'a çıkılamaz.
4. **İnternete açıldığı gün koruma zayıf (A3+A8).** Global rate limit yok, brute-force koruması restart'ta sıfırlanıyor, hata izleme/yapısal log yok → olay anında kör uçuş.
5. **Veri büyümesi tuzağı (C5).** İnline base64 ekler + 20k öğrenci seed gerçeği → backup/restore süreleri ve tablo şişmesi pilotta sürpriz üretir.
6. **Bus factor + doküman drift'i.** 7 günde yazılmış ~500 dosya, dört "kanonik" plan dokümanı arasında durum çelişkileri (assessment kendisi de bunu söylüyor). Tek doğruluk kaynağı seçilmeden ekip/agent ölçeklemesi riskli.

## 6. Yeni Çözüm / Kütüphane / Teknoloji Önerileri

Hepsi mevcut stack'e ek; hiçbiri mimari değiştirmez. Sıra = önerilen uygulanma sırası.

### 6.1 API istek validasyonu: Zod + hafif Nest pipe

- **Öneri:** `zod`'u (web'de zaten var) API'ye bağımlılık yapıp tek bir `ZodValidationPipe` ile kritik controller'lara bağlamak; şemalar `packages/shared-types`'ta.
- **Problem:** API'de DTO validasyon katmanı yok (A7); elle kontroller tutarsız, 422 sözleşmesi garanti değil.
- **Stack uyumu:** Monorepo zaten Zod kullanıyor (web formları, `form-validation.ts` 17K); shared-types tek kaynak hedefi MASTER_PLAN §3.1'de yazılı.
- **Alternatifler:** `class-validator` (Nest standardı ama ikinci şema dili olur), `nestjs-zod` (ek bağımlılık, sürüm takibi).
- **Neden bu:** Tek şema dili; web formu ↔ API sözleşmesi aynı dosyadan türür; pipe ~50 satır, kütüphane bile gerekmez.
- **Maliyet/bakım:** Düşük; şema disiplinini sürdürme maliyeti.
- **Güvenlik/KVKK:** Pozitif — mass-assignment ve tip karmaşası azalır; PII alanlarında format zorlaması.
- **Risk:** Sıkı şema mevcut istemcileri kırabilir → shadow-validation (logla, reddetme) ile başla.
- **POC:** `auth.controller` + `student.controller`'a pipe; 422 e2e testleri.
- **Başarı kanıtı:** Geçersiz gövdeye alan-bazlı 422; mevcut e2e regresyonsuz.
- **Geri alma:** Pipe kaydını kaldır; şemalar tip olarak kalır.

### 6.2 Rate limit: `@nestjs/throttler` + Redis store; login limiter'ın Redis'e taşınması

- **Öneri:** Global `@nestjs/throttler` (Redis storage ile) + `LoginAttemptLimiter`'ın Redis'e taşınması ve anahtarın `email+IP` olması.
- **Problem:** A3 — internete açık API'de global limit yok; mevcut kilit restart'ta uçuyor, tek başına e-posta anahtarı hedefli kilitleme DoS'una açık.
- **Stack uyumu:** Redis zaten zorunlu altyapı (BullMQ).
- **Alternatifler:** Traefik rate-limit middleware (IP bazlı, uygulama bağlamı yok — tamamlayıcı olarak ayrıca önerilir), `rate-limiter-flexible`.
- **Neden bu:** Nest-native, decorator ile uç bazlı ayar; login için mevcut sınıf arayüzü korunarak store değişir.
- **Maliyet/bakım:** Düşük.
- **Güvenlik/KVKK:** Pozitif; IP işlenmesi KVKK envanterine eklenir (meşru menfaat, log saklama süresiyle).
- **Risk:** Yanlış eşik gerçek kullanıcıyı engeller → önce ölçüm modu, tenant başına makul eşik.
- **POC:** `/auth/login` + `/auth/refresh`'te 5/dk eşik; k6 ile 429 kanıtı; API restart sonrası kilidin sürdüğü test.
- **Başarı kanıtı:** k6 koşusunda eşik üstü 429; restart sonrası kilit kalıcı; `rate_limit_redis_smoke` artifact'i hash'li IP/e-posta, iki instance, exact command-set ve boş `gaps` ile doğrulanır.
- **Geri alma:** Guard'ı kaldır; limiter in-memory implementasyona geri döner (interface aynı).

### 6.3 Hata izleme: `@sentry/node` + `@sentry/nextjs` gerçek entegrasyon (alternatif: self-host GlitchTip)

- **Öneri:** API+worker'a `@sentry/node`, web'e `@sentry/nextjs`; `sendDefaultPii:false`, `beforeSend`'de TC/telefon/e-posta maskeleme. Veri ikametgâhı sertse aynı SDK ile self-host **GlitchTip** (Sentry-uyumlu, TR VPS'te çalışır).
- **Problem:** A8 — README iddiasına rağmen runtime hata yakalama yok; pilotta hatalar görünmez.
- **Stack uyumu:** `SENTRY_*` env'leri, smoke script'i ve prod-readiness maddeleri zaten var; sadece SDK eksik.
- **Alternatifler:** GlitchTip (self-host, KVKK avantajı, bakım yükü sende), yalnız Loki'ye log (arama var, issue gruplama/uyarı yok).
- **Neden bu:** En kısa yol; mevcut kanıt zinciri (`sentry:smoke`) SDK üzerinden gerçek olaya dönüşür.
- **Maliyet/bakım:** SaaS Sentry ücretli kademe olası; GlitchTip'te +1 servis bakımı.
- **Güvenlik/KVKK:** SaaS Sentry'de hata verisi yurt dışına gider → maskeleme zorunlu, aydınlatma metnine işlenir; tam TR ikamet isteniyorsa GlitchTip seçilir (karar DEC'e).
- **Risk:** Gürültülü hata seli → örnekleme + ortam ayrımı.
- **POC:** Worker'da bilinçli job hatası → issue'da tenantId etiketli, PII'siz görünüm.
- **Başarı kanıtı:** Bilinçli hata 1 dk içinde panelde; alert webhook'a düşer.
- **Geri alma:** SDK init'i env flag'iyle kapatılır; bağımlılık sökümü tek PR.

### 6.4 Yapısal log: `pino` + `pino-http`

- **Öneri:** API ve worker'da pino JSON log; requestId/tenantId/userId alanları; `redact` ile PII listesi; Nest logger köprüsü.
- **Problem:** A8 — console log'larla Loki'de korelasyon/filtreleme yapılamıyor; PII sızıntı riski denetlenemiyor.
- **Stack uyumu:** Alloy→Loki hattı kurulu; JSON loga geçince mevcut Grafana panelleri anlamlanır. MASTER_PLAN §7 zaten pino'yu hedeflemiş.
- **Alternatifler:** winston (daha ağır), nestjs-pino (kolay ama ek soyutlama).
- **Neden bu:** En hızlı JSON logger; redaction yerleşik.
- **Maliyet/bakım:** Düşük.
- **Güvenlik/KVKK:** Pozitif — redaction merkezi.
- **Risk:** Log hacmi artışı → Loki retention ayarı (15d mevcut Prometheus'ta; Loki için de sınır konur).
- **POC:** Request log'unda `{requestId, tenantId, path, status, durationMs}`; Loki'de tenant filtreli sorgu.
- **Başarı kanıtı:** Grafana'da tek requestId ile API+worker korelasyonu.
- **Geri alma:** Logger köprüsü kaldırılır; console'a döner.

### 6.5 Upload AV: ClamAV (clamav/clamav container) + fail-closed kuyruk taraması

- **Öneri:** backend_net'e ClamAV servisi; upload'lar S3'e "pending" yazılır, tarama sonrası "clean" işaretlenir; EICAR reddi testi. Açık "AV sağlayıcı" onay maddesini kapatır.
- **Problem:** A5 — AV kararı bloklayıcı onay listesinde; magic-byte tek başına yetersiz.
- **Stack uyumu:** Compose'a +1 servis; `upload-av:check` kanıt sözleşmesi zaten bu kararı bekliyor.
- **Alternatifler:** Bulut AV API'leri (dosya yurt dışına çıkar — KVKK'da öğrenci verisi için uygun değil), tarama yok (kabul edilemez — fail-closed şartı checklist'te).
- **Neden bu:** Self-host, ücretsiz, TR ikametgâh korunur.
- **Maliyet/bakım:** ~1-2 GB RAM + imza güncelleme; düşük-orta.
- **Güvenlik/KVKK:** Pozitif; dosya dışarı çıkmaz.
- **Risk:** Büyük dosyada tarama gecikmesi → async tarama + "taranıyor" durumu.
- **POC:** Destek eki yüzeyinde EICAR → reddedilir + audit; temiz dosya → indirilebilir.
- **Başarı kanıtı:** `pnpm upload-av:check` gerçek raporla PASS.
- **Geri alma:** Servis kapatılır; fail-closed bayrağı upload'u "yalnız magic-byte" moduna döndürmez — **bilinçli karar gerekir** (stop-rule).

### 6.6 API sözleşmesi: `@nestjs/swagger` ile OpenAPI üretimi

- **Öneri:** Minimal dekorasyonla OpenAPI JSON üretimi + CI artefaktı; UI yalnız dev ortamında.
- **Problem:** A7 — 37 controller'lık API'nin makine-okunur sözleşmesi yok; web/dış entegrasyon el ile.
- **Stack uyumu:** Nest resmi modülü; mevcut zarf (`{data, meta}`) şemalanır.
- **Alternatifler:** zod-openapi (6.1 ile birleşik üretim — orta vadede daha şık; ilk adım için swagger daha hızlı), elle yazılmış sözleşme (drift garantili).
- **Neden bu:** Düşük efor, anında envanter; 6.1 olgunlaşınca zod-openapi'ye evrilebilir.
- **Maliyet/bakım:** Düşük; dekorasyon disiplini.
- **Güvenlik/KVKK:** Prod'da UI kapalı; JSON yalnız iç kullanım.
- **Risk:** Yarım dekorasyon yanıltıcı doküman üretir → kritik modüllerden başla, kapsam rozeti.
- **POC:** auth+student+exam modülleri için spec; spec'ten örnek istemci üretimi.
- **Başarı kanıtı:** CI'da `openapi.json` artefaktı; spec diff'i PR'da görünür.
- **Geri alma:** Modül kaydı kaldırılır.

### 6.7 Kuyruk operasyonu: `@bull-board/api` self-host panel

- **Öneri:** Ayrı küçük express servisi (backend_net, basic-auth) ile bull-board; failed job görüntüleme/yeniden deneme.
- **Problem:** C6 — failed job'lara bugün yalnız redis-cli ile bakılabiliyor; pilot operasyonunda kör nokta.
- **Stack uyumu:** BullMQ resmi ekosistemi; mevcut kuyruk adlarıyla çalışır.
- **Alternatifler:** Taskforce.sh (SaaS — Redis erişimi dışarı açılır, KVKK/secret riski: reddedilir), kurum panelindeki kanıt ekranlarını genişletmek (daha çok iş; uzun vadede istenebilir).
- **Neden bu:** 1 saatlik kurulum, operasyon görünürlüğü.
- **Maliyet/bakım:** Çok düşük; admin-only erişim şart.
- **Güvenlik/KVKK:** Job payload'larında PII olabilir → panel yalnız VPN/iç ağ + basic-auth; payload'larda PII minimizasyonu zaten ilke.
- **Risk:** Yanlışlıkla public expose → Traefik'e bağlanmaz, yalnız SSH tüneli.
- **POC:** Staging'de failed sms-batch job'unun panelden retry'ı.
- **Başarı kanıtı:** Failed→retry→completed akışı panelden, audit notuyla.
- **Geri alma:** Servis silinir; sıfır iz.

### 6.8 Ek depolama: S3 imzalı URL + inline-base64 sökümü

- **Öneri:** Materyal/destek eklerinde S3 (MinIO mevcut) + kısa ömürlü imzalı GET; `contentBase64` yazımının kapatılması; mevcut kayıtlar için onaylı taşıma.
- **Problem:** C5 — DB şişmesi, backup süresi, satır kilitleri.
- **Stack uyumu:** S3 istemcisi, bucket bootstrap (minio-setup) ve `storageKey` alanı zaten var; RawImport zaten S3'te.
- **Alternatifler:** Postgres Large Objects (operasyonel yük), olduğu gibi bırakmak (10k ölçeğinde patlar).
- **Neden bu:** Yarısı yapılmış işin tamamlanması; yeni teknoloji değil.
- **Maliyet/bakım:** Düşük; MinIO yedeği backup planına eklenir (off-site smoke kapsamına).
- **Güvenlik/KVKK:** İmzalı URL süresi ≤ 5 dk; bucket private; erişim audit'i korunur.
- **Risk:** Taşıma sırasında kayıp → sha256 doğrulamalı kopya + çift-okuma dönemi. **Stop-rule: mevcut kayıt taşıma script'i açık onay env'i olmadan çalışmaz.**
- **POC:** Yeni destek eki S3'e; indirme imzalı URL ile; e2e güncellenir.
- **Başarı kanıtı:** DB'de yeni `contentBase64` satırı yok; ek indirme e2e yeşil; tablo boyut raporu.
- **Geri alma:** Env flag ile inline moda dönüş (eski yol silinmeden bir sürüm bekler).

### 6.9 Dış izleme: Uptime Kuma (self-host)

- **Öneri:** Ayrı küçük VPS/container'da Uptime Kuma; `/health`, `/health/ready`, web login sayfası ve Traefik TLS sertifika süresi izlenir; webhook → mevcut alert kanalı.
- **Problem:** İç Prometheus dışarıdan erişilebilirliği ölçmez; "site açılmıyor"u ilk müşteri haber vermesin.
- **Stack uyumu:** Bağımsız; mevcut `ALERT_WEBHOOK_URL` kanalını kullanır.
- **Alternatifler:** UptimeRobot (SaaS, ücretsiz kademe; veri minimal — kabul edilebilir ikinci seçenek), Grafana synthetic (ek karmaşıklık).
- **Neden bu:** Self-host, 10 dk kurulum, sertifika süresi uyarısı dahil.
- **Maliyet/bakım:** Çok düşük.
- **Güvenlik/KVKK:** Yalnız public endpoint'lere bakar; veri içermez.
- **Risk:** İzleme node'u tek nokta → ikincil olarak UptimeRobot eklenebilir.
- **POC:** Staging URL izleme + bilinçli kesinti alarmı.
- **Başarı kanıtı:** Kesinti < 2 dk içinde webhook'ta.
- **Geri alma:** Container silinir.

### 6.10 (Koşullu) Yönetici girişlerine TOTP MFA: `otplib`

- **Öneri:** SYSTEM_ADMIN ve TENANT_ADMIN için isteğe bağlı→zorunlu TOTP; kurtarma kodları; passkey v2'ye ertelenir.
- **Problem:** Tüm kurum verisine erişen hesaplar tek faktörlü; KVKK "uygun teknik tedbir" beklentisi.
- **Stack uyumu:** AuthSession/refresh altyapısına ek bir doğrulama adımı; şema ek alan (`User.totpSecretEncrypted`).
- **Alternatifler:** SimpleWebAuthn/passkey (UX iyi ama cihaz yönetimi + destek yükü; v2), SMS OTP (maliyet + SIM-swap riski: reddedilir).
- **Neden bu:** Bağımlılık küçük, ofis dışı saldırı yüzeyini ciddi daraltır.
- **Maliyet/bakım:** Orta-düşük; destek süreci ("telefonumu kaybettim") runbook ister.
- **Güvenlik/KVKK:** Pozitif; secret şifreli saklanır (mevcut PII şifreleme deseniyle).
- **Risk:** Kilitlenen admin → kurtarma kodu + sistem admin reset akışı şart.
- **POC:** Tek tenant'ta opt-in TOTP; login e2e.
- **Başarı kanıtı:** TOTP'suz login 401; reuse/rotation regresyonu yeşil.
- **Geri alma:** Feature flag kapatılır; alanlar dormant kalır.
